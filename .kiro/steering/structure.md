# Project structure

```
manifest.json                MV3 config: permissions, content-script order, CSP, commands
data/defaultPrompts.js       The 136 built-in prompts (code, not data on disk)
lib/                         Shared libraries, ES5, no DOM assumptions
  promptStore.js             Storage, migration, ranking, categories/folders, favourites, sync,
                             backups, history, licensing, free limit (single source of truth)
  template.js                Placeholder parsing, labels, auto-fill, rendering, context blocks
  modifiers.js               The 12 right-click quick modifiers
  importers.js               JSON, AIPRM, CSV/TSV, Markdown, SKILL.md, plain-text adapters
                             (popup and options pages only; not a content script)
  theme.js                   Resolves light / dark / system into data-theme attributes
content/                     Injected into curated AI sites by default; dynamic registration or activeTab on-demand on other sites
  adapters.js                Composer detection, caret-safe insertion, landing check, auto-send (SITES table)
  slashTrigger.js            The // menu
  commandPalette.js          The Alt+K overlay
  variableModal.js           The fill-in form with live preview
  content.js                 Coordinator: shadow host, messages, clipboard fallback (loads last)
  content.css                Styles inside the shadow root (web accessible)
styles/base.css              Design tokens and controls for popup, options and welcome pages
popup/                       Toolbar popup
options/                     Library, editor, settings, backup & sync, Pro
background/background.js     Service worker: context menus, commands, injection into open tabs, snapshots
welcome/                     First-run guide and role onboarding
test/harness.js              Node vm realm with fake chrome.storage and a minimal DOM
test/verify.js               Regression suite (node test/verify.js)
test/test-page.html|.js      Offline manual sandbox
icons/                       Generated by generate-icons.js
dist/                        Release zips (manual)
backups/                     Manual source snapshots; not referenced by code, do not edit
```

## Where things go
- Storage, settings, limits, licensing, anything persisted: `lib/promptStore.js`. No other file reads or writes prompt storage keys directly; go through `OmniStore`.
- Template syntax or auto-fill: `lib/template.js`.
- New import format: `lib/importers.js` (skip malformed rows, never overwrite a built-in).
- Per-site composer quirks: the `SITES` table in `content/adapters.js`.
- New built-in prompt: `data/defaultPrompts.js`, then update counts in the README and tests.
- Shared page styling: tokens in `styles/base.css`; content-script styling in `content/content.css`.

## Script load order (tested)
Content scripts, in this exact order: `data/defaultPrompts.js`, `lib/theme.js`, `lib/template.js`, `lib/modifiers.js`, `lib/promptStore.js`, `content/adapters.js`, `content/variableModal.js`, `content/slashTrigger.js`, `content/commandPalette.js`, `content/content.js` (always last). `CONTENT_SCRIPTS` in `background/background.js` must equal this list (tested).

`lib/importers.js` is loaded only by `popup.html` and `options.html`, the two pages that import files. It is not a content script and the service worker does not `importScripts` it; without it `OmniStore.importBundle` still reads OmniPrompt JSON and returns `ok: false` for other formats (tested in §1b). It stays in `LIB_FILES` and the `testSyntax`/`shipped` lists.

When adding or renaming a shipped script, update all of:
1. `manifest.json` → `content_scripts[0].js` (if it is a content script).
2. `CONTENT_SCRIPTS` in `background/background.js` (re-injection into open tabs) and its `importScripts(...)` list if the service worker needs it.
3. The `<script>` tags in `popup.html`, `options.html` or `welcome.html` if those pages use it.
4. The `testSyntax` file list and the `shipped` network-check list in `test/verify.js`, and `LIB_FILES` in `test/harness.js` for libs.

## Storage keys
`STATE_KEYS` in `lib/promptStore.js` is the one list `load()` and `watchStorage()` read. `applyLoaded()` resets any key it does not receive, so a new persisted key must be added to `K`, `STATE_KEYS`, `DELTA_KEYS` (if it is the user's data), `syncPayload`/`mergeRemote` (if it syncs) and the README table. Section 39 of the suite catches a missing one.

All defined in object `K` at the top of `lib/promptStore.js` and exported as `OmniStore.KEYS`. Schema v2 stores only deltas: `omni.userPrompts`, `omni.defaultPatches`, `omni.hiddenDefaults`, plus `omni.customCategories`, `omni.folders`, `omni.favorites`, `omni.usage`, `omni.settings`, `omni.license`, the Pro keys `omni.workspaces`, `omni.variableSets`, `omni.chains`, `omni.tombstones`, `omni.customModifiers`, `omni.siteRules`, and others. `omni.snapshots`, `omni.history`, `omni.backupMeta`, `omni.pendingDraft`, `omni.lastValues`, `omni.folderSyncMeta`, `omni.compareTargets` and the licence are local-only and never synced. Transient compare job state lives in session storage (`omni.compare.<tabId>`). The folder-sync directory handle is the one thing outside `chrome.storage`: it lives in the options page's IndexedDB (`omniprompt-folder-sync`), because only IndexedDB can hold a file handle. Legacy v1 keys (`custom_prompts`, `prompts_override`, ...) are read only by migration and left on disk. If you add a key, add it to `K` and to the README storage table.

## Theming
- Tokens are unprefixed CSS variables (`--bg`, `--surface`, `--text`, `--accent`, `--good`, `--warn`, `--danger`, `--r-md`, `--shadow-1`, ...) in `styles/base.css` under `:root` and `[data-theme='dark']`.
- `content/content.css` re-declares them on `:host` and `:host([data-omni-theme='dark'])`.
- `OmniTheme.apply()` sets the attribute; do not add `prefers-color-scheme` media blocks.
- Content UI always renders inside the open shadow root on `#omniprompt-root`; never inject styles or elements into the host page outside it.
